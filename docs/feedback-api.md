# Feedback API

> **Implemented** in `apps/backend` (`routes/feedback.route.ts`, `services/feedback-query.service.ts`).
> Reports are generated by Gemini in the background when an interview ends
> (`services/feedback-report.service.ts`) and stored in `InterviewReport`; per-role
> aggregates live in `RoleFeedback` and goals in `FeedbackGoal` (see `packages/database/prisma/schema.prisma`).
>
> - `roleId` is the interview role slug (e.g. `frontend-engineer`); `category` is the role's short track name (e.g. `Frontend`).
> - Only sessions whose report is `READY` are returned. All scores are 0-100.
> - Auth: `token` header, `Authorization: Bearer <jwt>`, or the `token` cookie. Missing/invalid auth returns `401`.
>
> Related interview endpoints:
> - `POST /api/interview/end` `{ sessionId }` — marks the session completed and queues the Gemini report.
> - `POST /api/interview/feedback` `{ sessionId }` — (re)generates the report synchronously and returns it.

The frontend expects JSON responses from the following authenticated endpoints. All requests include credentials and use the API base URL configured by `NEXT_PUBLIC_API_URL`.

## Shared types

```ts
type FeedbackSkillScore = Record<string, number>;

interface FeedbackQuestion {
  text: string;
  score: number;
  strongerAnswer: string | null;
}

interface FeedbackSession {
  id: string;
  createdAt: string; // ISO 8601
  durationMin: number;
  role: string;
  category: string;
  roleId: string;
  score: number;
  skillScores: FeedbackSkillScore;
  topics: string[];
  feedbackNote: string | null;
  questions: FeedbackQuestion[];
}

interface FeedbackGoal {
  targetScore: number;
  targetDate: string | null; // ISO 8601 date
  label: string;
}
```

## `GET /api/feedback/summary`

Returns the aggregate values used by the summary row.

```json
{
  "totalSessions": 12,
  "averageScore": 74.5,
  "passRate": 0.6667,
  "passThreshold": 70,
  "weakestSkill": "technicalDepth",
  "lastUpdatedAt": "2026-10-21T10:30:00.000Z",
  "goal": {
    "targetScore": 85,
    "targetDate": "2026-12-01",
    "label": "Reach a consistent interview-ready score"
  }
}
```

`averageScore`, `passRate`, `weakestSkill`, `lastUpdatedAt`, and `goal` may be `null` when there is not enough data.

## `GET /api/feedback/sessions`

Query parameters:

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `category` | string | no | Exact category filter |
| `q` | string | no | Search text for role, category, or topics |
| `sort` | `newest \| oldest` | no | Sort order |
| `cursor` | string | no | Pagination cursor |
| `limit` | number | no | Maximum number of sessions |

## `GET /api/feedback/frequency`

```json
{
  "weeks": [
    {
      "weekStart": "2026-10-05",
      "sessionCount": 2
    },
    {
      "weekStart": "2026-10-12",
      "sessionCount": 0
    }
  ]
}
```

Weeks with no practice should be returned with `sessionCount: 0` so the chart can preserve empty weeks.

## `GET /api/feedback/goal`

```json
{
  "goal": null
}
```

When a goal exists, `goal` contains the `FeedbackGoal` shape shown in the summary example.

### Fields the backend must compute:

1. **Role Resolution**: Validate `roleId` against supported role tracks. Return HTTP `404` if the roleId is unknown or does not belong to the authenticated user.
2. **Session Filtering & Ordering**: Filter the authenticated user's session history by `category` or `roleId` matching the resolved role, sorted descending by `createdAt`.
3. **Latest Session**: Extract the most recent session (`sessions[0]`), or `null` if the candidate has zero completed interviews for this role.
4. **Pass Threshold**: Target threshold benchmark configured for this track (e.g. 70).
5. **Per-Skill Aggregation**: For each evaluated skill dimension:
   - `latest`: Candidate's score from `latestSession` (or `null` if no sessions).
   - `average`: Mean score across all sessions for this role.
   - `sessionCount`: Total sessions where this skill was scored.
6. **Strengths Extraction**: Top questions from this role's sessions with `score >= passThreshold`, sorted highest score first (capped at 3).
7. **Gaps Extraction**: Lowest questions from this role's sessions with `score < passThreshold`, sorted lowest score first (capped at 3).
8. **Recurring Gaps**: Repeated weaknesses identified across 2+ sessions in this role where scores fell below the benchmark.
9. **Next Step**: Dynamic recommendation string targeting the candidate's lowest-scoring skill in this track.
10. **Other Categories**: List of available role categories and their `roleId` identifiers for navigation.

## Errors

The frontend treats HTTP `401` as an expired authentication session and redirects to `/auth/signin`. HTTP `404` indicates an unknown or unauthorized roleId and displays the role not-found state with a link back to All Feedback. Other non-2xx responses display an inline error with a Retry button.
